📋 Message Logging Examples

The Console panel in DevTools displays messages logged by your application. Different log levels help categorize messages:

1.1 Log Info

Used for informational messages about the application's state and operations.

console.info("ℹ️ [INFO] Pet was just fed! Happiness is now: 9");

In DevTools: Shows as a regular message with an info icon (ℹ️)

  • Appears in Console tab
  • Blue info icon next to message
  • Use for non-critical application events

1.2 Log Warning

Used for potential issues or warnings that shouldn't occur during normal operation.

console.warn("⚠️ [WARNING] Pet happiness is dropping: 5");

In DevTools: Shows as a warning with yellow background and warning icon (⚠️)

  • Yellow warning background in console
  • Visible in Console and Issues tab
  • Use for conditions that should be investigated

1.3 Log Error

Used for actual errors in the application.

console.error("❌ [ERROR] Pet weight is critically low: 0");

In DevTools: Shows with red background and error icon (❌)

  • Red error background in console
  • Increments error counter at top of console
  • Use for exceptional conditions

1.4 Log Table

Display objects and arrays as formatted tables in the console.

console.table(petInfo);
console.table(petHistory);

In DevTools: Renders data as an HTML table

  • Organized columns for object properties
  • Sortable by clicking column headers
  • Great for viewing structured data

1.5 Log Group

Organize console messages into hierarchical groups that can be collapsed/expanded.

console.group("🐱 Pet Interaction Group");
console.log("User clicked Treat button");
console.log("Happiness updated");
console.groupEnd();

In DevTools: Messages appear nested with collapsible arrow

  • Creates collapsible section in console
  • Supports nested groups (console.group within group)
  • Improves console readability for complex operations

1.6 Log Custom

Style console messages using CSS to make them stand out.

const style = "color: #ff6b9d; font-size: 16px; font-weight: bold;";
console.log("%c🎀 Custom Styled Message!", style);

In DevTools: Appears with custom styling (colors, sizes, fonts)

  • Use %c placeholder for styled section
  • CSS style properties can be applied
  • Multiple %c styles in one message

🔍 View Messages Logged by the Browser

Chrome automatically logs errors and issues that occur in your application:

2.1 Cause 404 Network Error

When you request a resource that doesn't exist on the server.

Step 1: Click "Cause 404 Error" button on the main page
Step 2: Open DevTools (F12)
Step 3: Go to Console tab
Step 4: Look for "❌ Network Error - 404"
Step 5: Go to Network tab to see the failed request in red
What to look for: Network tab shows GET request with 404 status code in red text

2.2 Cause TypeError

When code attempts an invalid operation on a variable.

Step 1: Click "Cause TypeError" button
Step 2: In DevTools Console, see "🔴 Deliberately causing a TypeError..."
Step 3: Look for error message about calling method on undefined
Step 4: Stack trace shows which line caused the error
What to look for: Red error message with file name and line number in stack trace

2.3 Cause Performance Violation

Long-running operations that block the main thread and cause performance issues.

Step 1: Click "Cause Performance Violation" button
Step 2: Go to Performance tab in DevTools
Step 3: Click the circle to record, then click button again
Step 4: Stop recording and view the performance timeline
Step 5: Look for a long continuous yellow/orange bar indicating heavy CPU usage
What to look for: Long task indicator in the Performance timeline

🔎 Filter Messages

Chrome DevTools provides powerful filtering capabilities in the Console:

3.1 Filter by Log Level

Show only messages of a specific severity level.

In Console tab: Click the filter funnel icon
Uncheck: "Errors", "Warnings", or "Logs" as needed
Result: Console shows only messages matching your filter

3.2 Filter by Text

Search for messages containing specific text.

Step 1: Click "Filter by Text Example" button
Step 2: In Console tab, type in the filter box at top
Step 3: Example: type "action" to see "User action" messages
Result: Only messages containing that text display

3.3 Filter by Regular Expression

Advanced text filtering using regex patterns.

Step 1: Click filter box and enable regex with icon
Step 2: Enter pattern like: /\[.*\]/
Result: Shows only messages matching the regex pattern

3.4 Filter by Message Source

Messages are tagged with their source module.

Step 1: Click "Show Message Sources" button
Step 2: Notice messages tagged like [PET-CONTROLLER], [UI-RENDERER]
Step 3: In filter box, type a source tag like "CONTROLLER"
Result: Shows only messages from that source

3.5 Filter by User Messages

Distinguish between browser-generated and application-generated messages.

User Messages: Created by console.log(), console.warn(), etc.
Browser Messages: Network errors, warnings, automated checks

🐛 Debugging & Breakpoints

Chrome DevTools Sources panel allows you to pause and inspect code execution:

4.1 Set a Line-of-Code Breakpoint

Pause execution at a specific line to inspect state.

Step 1: Open DevTools (F12) → Sources tab
Step 2: Find the file: script.js
Step 3: Click on a line number to set a breakpoint (blue dot appears)
Step 4: Click a demo button that triggers that code
Step 5: Execution pauses at the breakpoint
Try this: Click "Variable Inspection" button and set a breakpoint in that function

4.2 Check Variable Values

When paused at a breakpoint, inspect variable values in multiple ways:

The Scope Pane

Shows all variables in the current execution context.

Location: Right side panel when paused at breakpoint
Contains: Local, Closure, and Global scopes
Expand objects: Click triangle to see nested properties

Watch Expressions

Manually enter expressions to evaluate while code is paused.

Step 1: In DevTools, click "Watch" section
Step 2: Click + to add expression
Step 3: Type expression like petInfo.happiness * 2
Step 4: Value updates as you step through code

The Console

Type commands directly in Console while paused at a breakpoint.

Step 1: When paused, open Console tab
Step 2: Type a variable name: petInfo
Step 3: See the current value of that variable
Step 4: Type expressions: petInfo.happiness + 5

4.3 Step Through Code

Execute code line by line to understand program flow.

Step Over (F10): Execute current line and move to next
Step Into (F11): Step into function calls
Step Out (Shift+F11): Execute until current function returns
Continue (F8): Resume execution until next breakpoint

4.4 Pause on Exception

Automatically pause when an error occurs.

Step 1: In DevTools Sources, look for pause icon (bottom-right)
Step 2: Click to select "Pause on uncaught exceptions"
Step 3: Click "Pause on Exception" button in the app
Result: Execution pauses at the exact line that throws

4.5 Reproduce a Bug

Systematic approach to debug the division-by-zero example:

Step 1: Open DevTools → Console tab
Step 2: Click "Reproduce Bug (Division by Zero)" button
Step 3: See "🐛 Reproducing a common bug: division by zero"
Step 4: Notice after 3 clicks you see "BUG DETECTED: Division resulted in Infinity!"
Step 5: Click button 3 times rapidly to see the bug trigger
What to look for: The bug only manifests when divisor equals 0 (on the 3rd click)

4.6 Apply a Fix

After identifying a bug, implement the fix in your code:

Original buggy code: const divisor = bugCounter === 3 ? 0 : bugCounter;
Fixed code: const divisor = Math.max(bugCounter, 1); // Ensure divisor is at least 1
Process: Edit code → Save → Refresh browser → Verify fix

📁 Get Familiar with the Sources UI

Understanding the Sources panel layout:

Panel Location Purpose
File Navigator Left side Browse all files loaded by the page
Code Editor Center Display source code with breakpoint indicators
Debug Panel Right side Watch expressions, scopes, call stack, and breakpoints
Console Bottom (drawer) Execute JavaScript while debugging

Key Features:

  • Breakpoint Column: Click line numbers to add/remove breakpoints
  • Conditional Breakpoints: Right-click line → Add conditional breakpoint
  • Logpoints: Log a message without pausing execution
  • Call Stack: Shows function call hierarchy when paused
  • Scopes: View Local, Closure, and Global variables
